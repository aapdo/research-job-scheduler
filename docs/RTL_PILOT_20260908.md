# First real-server RTL scheduler pilot — 2026-09-08

Scope: one small CPU-only RTL simulation job on CPS2, using an isolated
pilot DB and a frozen copy of the extended scheduler. No production GPU
controller/DB change, package installation, Vivado build, or board operation.
CPS2 was not part of the production GPU scheduler inventory. Its live RAM,
disk and D-state checks passed; the pilot reserved one CPU, 256 MiB RAM and
64 MiB disk, with zero GPU and full-build slots.

## Result

The corrected pilot registered a real `rtl_sim` job, passed three stable
resource polls, then launched it through the scheduler's SSH transport and
detached agent. Icarus compiled and executed the actual NHWC packer/unpacker
RTL and existing roundtrip testbench for channels 1, 3, 5, 16, 24, 31, 32 and
48, with three pixels per case and backpressure checks.

* All eight cases passed; final marker `PASS RTL_SCHEDULER_PILOT cases=8`.
* Scheduler status `succeeded`, return code 0, validation status `pass`.
* One attempt in the corrected pilot; dry-run created no attempts.
* Reconstructing the controller and executing another tick did not create a
  duplicate attempt.
* RESULT.json, preflight.log and stdout.log were retrieved and their SHA256
  values matched the scheduler receipts.
* Both pilot nodes were disabled after their terminal decisions. No ongoing
  pilot dispatch loop remains.

## First-attempt failure and correction

The initial attempt is retained at
`/home/jy/experiments/rtl_scheduler_pilot_20260908_1638/`.
CPS2's PATH selected `/usr/local/bin/iverilog` 12.0, which reported a version
but could not find its `ivlpp`/`ivl` compiler backends. Compilation exited
127; the wrapper exited 1, and the scheduler marked failure with no success
receipt or automatic retry.

The correction used the already-installed complete `/usr/bin/iverilog` and
`/usr/bin/vvp` 11.0 explicitly. No system PATH, SSH config, compiler install,
or main-thread script was modified. A private SSH config applied only to
the pilot process. The new preflight also compiles and runs a tiny RTL case,
so version output alone is no longer its usability check.

A small local agent improvement clears a completed preflight's reason before
starting the workload and reports the actual workload exit code on failure.
Its regression test covers the misleading stale preflight reason observed
in the first attempt. Frozen pilot logs and releases are not rewritten.

## What remains unverified

This proves the real SSH/CPU/RTL registration, scheduling, execution, result
validation and receipt path. It does not establish full-detector correctness,
Vivado full-build scheduling, board locking on real hardware, or production
GPU/RTL co-scheduling. Deployment into the production controller and board
entry-wrapper integration remain separate rollout steps.
