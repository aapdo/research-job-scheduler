# Scientific scheduler recovery — 2026-09-09

The LAB2 inventory was accepted by repository schema but rejected by the actual
scientific controller deployment (`physical_host` was not an allowed node field).
The policy loop therefore failed before normal resource refresh/reconciliation.
Existing remote training continued independently, but completion observation,
artifact transfers and new dispatch stalled.

The deployed schema now validates the optional physical-host identifier, matching
the repository contract. All 14 registered nodes were validated with the actual
imported schema before restarting only the dispatcher. Existing attempt specs and
remote scientific workers were preserved. A deployment-compatibility regression
test and AGENTS.md registration check were added.

Two additional dispatch-path issues were repaired:

1. Artifact placement now copies only modified dependency-location maps, not the
   full historical attempt/report graph for every candidate. This avoids spending
   the health freshness window copying unrelated records.
2. Legacy SIX packing-release migration is limited to project `cg-six-way`.
   Prefix matching had rewritten the independent `cg-six-band` v3 release to the
   older SIX release, whose band configuration file does not exist. Fourteen
   resulting pre-training validation failures were preserved; all 55 band job
   paths were restored from immutable experiment registration and those failed
   jobs received explicit additional attempts. No scientific checkpoint was reset.

Live verification after repair: all 18 SIX band training jobs reached `running`
on existing servers; resource snapshots/STATE resumed and an HF upload was observed.
The LAB2 source-inventory failure was the same nonexistent rewritten band path,
not corrupt image bytes. Its prior configuration is preserved as
`CONFIG.pre_mapping_repair.json`; revision 2 uses registered band-v3 paths.

`lab2-data-preparation.service` was restarted with the user's expanded authority:
verified direct LAB3-to-LAB2 data transfer, image/hash/owner/runtime verification,
private HF access setup, actual-schema-validated LAB2 activation, compatible queued
job host expansion, then observation of its first normal scheduler assignment.
No dataset includes credentials, and no new dispatcher is created for LAB2.
